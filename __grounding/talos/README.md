# Talos workflow evaluation and decision system (work in progress)

**Status:** Work in progress — design and draft prompt specification only. Talos is not wired into the running server or operator UI.

**Talos** is the product name for Heavy Rain's planned workflow discovery, recurrence evaluation, and routing decision layer, replacing the earlier **Cairn** product name. The **Heavy Rain** platform name and **Relay** intake and builder coordination service name remain unchanged.

To preserve compatibility with existing tests, fixtures, and local runtime checks, current Python packages (`services/cairn`), classes (`CairnOrchestrator`, `CairnCoordinatorConfig`), `/health` payload fields (`cairn`), and routes (`POST /api/v1/orgs/{org_id}/batches/review-with-cairn`) retain `cairn` and `Cairn` identifiers in code.

## Documents in this directory

- [`./system-design.md`](./system-design.md) — Proposed architecture, current runtime boundaries, recurrence deduplication rules, disposition gates, current vs. proposed security and budget controls, and staged rollout plan.
- [`./contracts.md`](./contracts.md) — Authoritative prompt composition protocol, placeholder inventory, input/output JSON contracts, host-side validation rules, and ten illustrative, unrun acceptance test cases.
- [`./prompts/coordinator.md`](./prompts/coordinator.md) — Draft system instructions for the planned Talos stage envelope coordinator.
- [`./prompts/assess-workflow.md`](./prompts/assess-workflow.md) — Draft prompt to evaluate consented report snapshots for provenance-backed recurrence, catalog fit, and counterevidence.
- [`./prompts/review-decision.md`](./prompts/review-decision.md) — Draft adversarial review prompt to challenge a proposed disposition against evidence, catalog entries, and policy.
- [`./prompts/prepare-build.md`](./prompts/prepare-build.md) — Draft handoff prompt to convert a host-validated, operator-authorized build decision into a bounded `LiveBuildRequest` payload for Relay's live builder.

## Implemented today vs. proposed in Talos

| Capability | Implemented in repository today | Proposed for Talos (work in progress) |
| --- | --- | --- |
| **Live builder (`services/relay/relay/live_builder.py`)** | Implemented. Calls the Gemini API via the Google Gen AI Python SDK (`interactions.create` with `agent="antigravity-preview-09-2026"`, `environment="remote"`, `background=True`, `store=True`), polls progress via `interactions.get`, supports `interactions.cancel`, exports files via `environments.files.list` and `environments.files.download`, records state in SQLite, and serves a self-contained static export (`scaffold.css`, `index.html`, `NOTES.md`, `preview.svg`, `card.json`) for human review. Accepts per-request `build_mode` (`"flash" \| "argon" \| None`) on `LiveBuildRequest`. | Consumes host-validated `LiveBuildRequest` briefs generated through `prepare-build.md` after host policy, target-cluster scope permission, effective token-limit, and operator authorization checks pass. |
| **Build modes (`flash` vs. `argon`)** | Per-request `build_mode` (`Literal["flash", "argon"] \| None`) is implemented in `services/relay/relay/models.py` and `services/relay/relay/live_builder.py`. An explicit `"flash"` or `"argon"` mode selects `gemini-3.8-flash` or `gemini-4-argon` and distinct builder prompts; `None` uses `LiveBuilderSettings.model` (`gemini-3.8-flash` by default; `gemini-4-argon` in the local server observation recorded on 2026-10-25). Mode-specific fidelity descriptions and workspace byte caps (`150,000` vs. `1,048,576` bytes) are prompt targets rather than guaranteed outcomes or mode-specific runtime validators today. | Talos-to-builder handoff (`BuilderConstraintsSnapshot`, `AuthorizationSnapshot.authorized_build_mode`, and `PrepareBuildOutput`) binds an explicit `"flash"` or `"argon"` `build_mode`, derives `BuilderConstraintsSnapshot.max_total_tokens` from effective `LiveBuilderService` settings (`self.settings.max_total_tokens`) within `authorized_max_total_tokens`, and proposes host-side validation of the `150,000`-byte (**Flash**) and `1,048,576`-byte (**Argon**) workspace targets. |
| **Progress narration (`services/relay/relay/narrator.py`)** | Implemented as an optional helper (`models.generate_content`, defaulting to `gemini-3.8-flash`) that rewrites builder step lines and falls back to raw step text on error. | Unchanged; remains a display helper in Relay. |
| **Weekly cluster evaluation (`services/cairn/cairn/clustering.py`)** | Deterministic Python rules over local fixtures producing the four current runtime dispositions: `reuse_existing_app`, `build_in_sandbox`, `request_missing_evidence`, or `queued_next_cycle`. | Multi-step model assessment (`assess-workflow.md`) with event/window recurrence deduplication, tri-state role/scope checks, explicit counterevidence, and a proposed fifth `do_not_build` disposition migration. |
| **Live model review (`services/cairn/cairn/live_review.py`)** | Optional single-call read-only check on `google-antigravity==0.1.22` (`review_prompt.txt`, `MAX_REVIEW_TOKENS = 16_384`, `MAX_REVIEW_OUTPUT_TOKENS = 4_096`, `REVIEW_TIMEOUT_SECONDS = 90`); disabled in the local server observation recorded on 2026-10-25 (`liveModelReviewEnabled: false`). | Dedicated adversarial review stage (`review-decision.md`), host-enforced cross-field validators, and a proposed `shadow_review_pending` operator comparison state. |
| **Tenant & build authorization** | Prototype UI switches organizations (`rookmere`, `augi`, `meridian`) and operator personas via unauthenticated demo selectors; callers post `LiveBuildRequest` payloads directly to Relay. | Host-evaluated `AuthorizationSnapshot` bound to organization, cluster, snapshot hashes, policy version, cleared scopes, trusted requester (`persona_id`, `name`, `role`), `idempotency_key`, build mode, token budget, and expiry timestamp, rechecked by Python host code immediately before dispatch. |
